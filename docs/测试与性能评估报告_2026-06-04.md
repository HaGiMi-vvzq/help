## 三、性能评估

### 3.1 已落地优化

| # | 优化项 | 位置 | 效果 |
|---|--------|------|------|
| 1 | GZip 响应压缩 | `main.py` | 所有 JSON 响应缩小 60-80%（500B+ 自动启用） |
| 2 | 需求列表 Redis 缓存 | `needs.py` | 首页 60s 缓存，命中时跳过数据库查询 |
| 3 | COUNT(*) 修复 | `need_service.py` | 从"加载全部行再数数"改为 `SELECT COUNT(*)`，内存 + 查询时间大幅降低 |
| 4 | 数据库复合索引 | `need.py`/`user.py`/`message.py` | needs: `(status,type)`/`(user_id)`/`(created_at)`，users: `(role,is_active)`，messages: 3 个 |
| 5 | 用户画像预计算 | `backfill_embeddings.py` | 语义搜索不再现场计算 embedding |
| 6 | 创建需求时清缓存 | `needs.py` | `cache_invalidate_pattern("needs:list:*")` |

### 3.2 已知瓶颈

| 瓶颈 | 严重度 | 说明 | 解决方案 |
|------|--------|------|----------|
| SQLite 串行写锁 | **高** | 多用户同时写时串行排队，写 QPS ≈ 10 | 上线用 PostgreSQL |
| 单进程 uvicorn | **高** | 仅用 1 个 CPU 核心 | 上线用 Gunicorn 4 worker |
| 语义搜索 O(n) | **中** | 每次匹配扫全量用户做余弦相似度 | 预计算向量 + faiss 索引 |
| N+1 查询 | **中** | `_build_need_response` 每条需求单独查申请状态 | 批量查询优化 |
| Redis 未部署 | **中** | 缓存代码就绪但开发机无 Redis | 仅在 Docker 生产环境生效 |
| Qwen3 模型未下载 | **低** | 用降级向量，精度和速度不如本地模型 | `python download_models.py` |

### 3.3 并发能力预估

| 操作 | 开发环境(QPS) | Docker 生产(QPS) | 瓶颈 |
|------|-------------|-----------------|------|
| 需求广场浏览 | ~50 | 500+ | SQLite → Redis+PostgreSQL |
| 用户注册/登录 | ~10 | 200 | SQLite 写锁 → PostgreSQL |
| 消息发送 | ~20 | 200 | SQLite → PostgreSQL + WebSocket |
| 匹配请求 | ~2 | 10 | AI 调用 + 全量扫描 → ARQ 异步 |
| 健康检查 | ~200 | 5000+ | Nginx 直接处理 |

**单台 4 核 8G 云服务器预估承载**: 3000-8000 并发用户日常使用。

### 4.3 潜在风险

| 风险 | 等级 | 说明 |
|------|------|------|
| WebSocket 连接内存泄漏 | **低** | `_ws_connections` 字典 key 数量随用户增长，目前无上限清理 |
| 审计日志文件无限增长 | **低** | `audit-YYYY-MM-DD.jsonl` 按天滚动但不自动删除旧文件 |
| SSE 流无超时关闭 | **低** | 前端关闭页面后连接可能残留，依赖 60s 超时 |
| 内存限流器无上限 | **低** | `_buckets` 字典永不清理过期 entry |
