# 黑客松评分核心能力映射

> 用途：帮助演示和答辩时把项目能力对应到赛事要求。赛事要求包括：提示词工程、上下文知识库、智能体应用、安全管控、接口集成、技能封装、大模型底座适配等核心能力。

## 1. 总体口径

本项目不是单一聊天机器人，而是一个面向校园协作场景的 AI Agent 工作台。用户输入需求、上传文件或表达参与意向后，Agent 会进行语义判断、信息追问、需求生成、候选人匹配、消息起草和状态推进。

推荐答辩口径：

“我们把大模型能力拆成可组合的 prompt、skill、agent 和事件链路。用户消息进入系统后，先经过语义路由判断真实意图，再根据场景调用文件分析、需求生成、向量匹配、重排解释、内容安全和上下文总结等能力，最终落到可执行的校园互助流程中。”

## 2. 能力映射表

| 赛事核心能力 | 项目中对应实现 | 演示时怎么讲 |
|---|---|---|
| 提示词工程 | `backend/app/prompts/` 下的 prompt 模板，包括语义路由、意图判断、文件分析、需求润色、匹配重排、私信起草 | 展示 PromptRegistry，把不同任务拆成结构化 prompt，而不是一个大提示词硬撑 |
| 上下文知识库 | 用户画像、技能标签、需求内容、行为日志、Agent 会话摘要、文件提取信息、技能图谱 | 说明 Agent 判断时会结合用户画像、历史需求、文件摘要和技能标签 |
| 智能体应用 | `IntentAnalyzerAgent`、`PlannerAgent`、`NeedCreatorAgent`、`SemanticSearchAgent`、`RerankAgent`、`MatchWatcherAgent` | 展示“用户输入 -> Agent 判断 -> 生成草稿 -> 匹配 -> 沟通”的多 Agent 协作链 |
| 安全管控 | `content_moderation` skill、权限校验、会话归属校验、XSS 文本渲染、防重复发布、API Key 不明文展示 | 强调不仅会生成内容，也限制越权、重复操作和敏感信息泄露 |

| 技能封装 | `SkillRegistry` 管理 `semantic_router`、`file_reader`、`tag_extraction`、`embedding`、`vector_match`、`explain_match`、`context_summarizer` 等 | 打开 `/api/skills` 展示系统已有技能列表 |

## 3. 新增能力：semantic_router 语义路由技能

本轮新增了 `semantic_router` skill，用来封装“接收用户消息后，自我推理语义并判断下一步该做什么”的能力。

### 3.1 解决的问题

过去 Agent 对用户语义的判断分散在硬编码关键词和意图模型里，容易出现两类问题：

- 用户说“帮我找现有需求”，系统误判成“我要发布需求”。
- 用户只说“发布组队需求”，系统过早生成粗糙草稿，没有继续追问技能和方向。

`semantic_router` 把这类判断统一封装为结构化技能。

### 3.2 输入

- `message`：用户原始消息。
- `user_context`：用户画像、技能、历史行为摘要。
- `file_context`：如果当前会话有文件，则传入文件摘要。

### 3.3 输出

输出包含：

- `intent`：例如 `publish_need`、`discover_needs`、`view_matches`、`upload_file`。
- `next_action`：例如 `start_publish_follow_up`、`recommend_existing_needs`。
- `semantic_frame`：结构化语义框架，包括用户目标、目标对象、是否想找已有需求、是否想创建新需求、缺失信息、实体。
- `safety_level`：安全级别。
- `rationale`：简短可审计判断理由，不输出完整思维链。

### 3.4 演示例子

输入：

`我想打算法比赛，帮我看看有没有这方面的组队需求`

输出重点：

- `intent = discover_needs`
- `next_action = recommend_existing_needs`
- `wants_existing = true`

输入：

`帮我发布一个蓝桥杯组队需求`

输出重点：

- `intent = publish_need`
- `next_action = start_publish_follow_up`
- `wants_create = true`
- `missing_information` 会提示还需要技能/方向、人数模式等信息。

## 4. 已有可展示 skill

可以在演示时打开后端 `/api/skills` 展示技能封装列表。

推荐讲其中 5 个：

- `semantic_router`：语义路由，判断用户真实意图和下一步动作。
- `file_reader`：读取比赛通知或项目文件，提取主题、技能、截止时间和潜在需求。
- `tag_extraction`：从用户资料或需求中提取技能标签。
- `embedding` + `vector_match`：把用户和需求转成向量并召回候选人。
- `explain_match`：把匹配结果转成可解释推荐理由。
- `content_moderation`：内容安全审核。
- `context_summarizer`：长会话上下文摘要，减少重复信息。

## 5. 已有 hooks / 事件链路

项目使用轻量事件总线 `EventBus` 作为 hooks 机制。

目前可讲的事件包括：

- `user_registered`：用户注册后初始化偏好档案。
- `need_published`：需求发布后触发日志与后续匹配。
- `feedback_received`：收到匹配反馈后触发反思/偏好更新。
- `agent_file_processed`：文件分析完成后通知 Agent 工作台。
- `agent_need_created`：Agent 创建需求后记录事件。
- `agent_match_completed`：匹配完成后通知用户。

答辩口径：

“我们没有把所有逻辑写死在一个接口里，而是用事件 hooks 把注册、发布、匹配、反馈和 Agent 状态更新解耦，后续可以继续扩展主动提醒和长期记忆。”

## 6. 还可以继续封装但赛前不建议重做的能力

这些适合答辩时作为后续规划，不建议明天演示前大改：

- `demo_guardrail`：演示模式保护 skill，用于阻止重置关键数据、暴露 API Key、误删演示需求。
- `need_quality_checker`：需求质量检查 skill，给草稿打分并提示是否缺少技能、时间、人数、交付物。
- `application_state_auditor`：申请状态审计 hook，定期检查已匹配需求是否还有待处理申请。
- `presentation_storyteller`：根据当前项目状态自动生成路演讲稿或 PPT 大纲。
- `memory_preference_updater`：根据用户选择、拒绝和反馈更新长期偏好。

赛前建议只重点讲 `semantic_router`、已有 skill 列表和事件 hooks，避免引入新风险。

## 7. PPT 可直接使用的一页

标题：

**AI 七层能力覆盖：从 Prompt 到 Agent 工作流**

页面内容：

- 提示词工程：结构化 PromptRegistry，覆盖语义路由、文件分析、需求生成、匹配解释。
- 上下文知识库：用户画像、技能标签、需求库、文件摘要、会话记忆。
- 智能体应用：IntentAnalyzer、Planner、NeedCreator、SemanticSearch、Rerank、MatchWatcher。
- 安全管控：内容审核、权限校验、XSS 防护、防重复发布、API Key 保护。
- 接口集成：FastAPI、模型 API 设置、MCP 工具、前端 API。
- 技能封装：SkillRegistry，`/api/skills` 可查看技能列表。
- 大模型底座适配：DeepSeek 生成、Qwen embedding/rerank、本地 fallback。

一句话收束：

“我们不是只调了一次大模型接口，而是把大模型能力封装成可路由、可组合、可审计的校园协作 Agent 工作流。”
