# 对话记忆与项目交接文档

## 1. 文档用途

这份文档用于提炼当前项目在最近连续对话中形成的关键上下文，方便在开启新对话时，让新的对话快速了解：

- 项目当前做到哪一步
- 已实现和已验证的功能
- 最近修复过的重要问题
- 当前推荐的演示路径
- 后续最值得继续推进的方向

## 2. 维护规则

### 2.1 固定更新约定

从现在开始，**每次用户明确提出“保存记忆”“更新记忆”“同步记忆”“写入记忆文档”这类要求时，都应更新这份文档**，而不是新建另一份平行记忆文档。

### 2.2 更新原则

- 只保留对后续工作有帮助的高价值上下文
- 不写流水账，优先写结论、状态、关键变更和待办
- 如果某项结论可能过期，要标明“需重新验证”
- 如果出现与本文档冲突的新实现，以最新代码和最新验证结果为准，并同步覆盖本文档

## 3. 项目一句话概述

这是一个面向校园协作场景的 **AI 互助与撮合平台**。  
核心目标是让用户能够：

- 发布需求并由 Agent 辅助完善、发布、匹配人选
- 查看已有需求并主动申请加入
- 通过 Agent 反向发现适合自己的需求
- 在匹配和申请后进入消息沟通

## 4. 当前产品定位

当前项目已经从“单向发布需求找人”升级为“**双边协作撮合**”：

- 发布方可以发需求、看匹配、比较候选人、联系对方
- 参与方可以看需求、主动申请、让 Agent 推荐适合自己的需求、起草申请消息

## 5. 当前整体状态

截至当前会话，项目已经达到：

- **可运行**
- **可演示**
- **主链路基本闭环**
- **经过多轮功能审计、契约测试、烟测和构建验证**

适合黑客松路演的主线已经具备。

## 6. 已完成的核心能力

### 6.1 用户与资料

- 登录与演示账号入口已具备
- 用户画像与资料编辑已具备
- 个人资料、技能标签、院校信息支持持久化

### 6.2 需求系统

- 支持发布需求
- 支持需求管理、关闭、重开、删除
- 支持我的需求页
- 支持需求详情页
- 支持需求广场浏览
- 需求发布页的表单内容和 AI 生成预览已支持本地草稿持久化，切换页面后返回不会丢失
- AI 生成/润色需求描述时会结合当前用户画像，并会遵守单人/多人选择模式，避免“单选却生成 2-3 个队友”这类冲突文案

### 6.3 匹配系统

- 支持为需求生成候选人匹配结果
- 支持匹配概览、候选人卡片、对比表
- 支持选择候选人
- 支持起草私信
- 支持删除需求时取消对应匹配任务，避免无效后台占用
- 匹配页起草私信已支持按“当前用户 + 当前需求”保存草稿，切换页面后不会丢失

### 6.4 双边申请系统

- 支持用户主动申请加入某个需求
- 支持发布者查看收到的申请
- 支持接受/拒绝申请
- 支持“我的申请”页面集中查看申请状态
- 需求详情页申请文案已支持按“当前用户 + 当前需求”保存草稿，Agent 起草后切换页面不会丢失
- Agent 起草申请文案已接入完整用户上下文，不再只依赖用户名和技能标签

### 6.5 消息系统

- 支持基于需求上下文的站内消息
- 支持从匹配页或申请页跳转到消息页
- 支持消息发送与会话刷新

### 6.6 Agent 系统

当前 Agent 已具备轻量闭环能力：

- 新建会话
- 聊天追问
- 上传文件分析
- 生成需求草稿
- 确认发布需求
- 任务时间线
- 主动建议
- 记忆摘要
- 知识搜索工作台
- 反向推荐适合用户参与的已有需求
- 起草申请消息
- 语义路由 skill：用于先判断用户真实意图，再决定是找已有需求、发布新需求、继续追问还是执行其他动作
- 发布需求前的追问已补齐“技能/方向”字段，避免用户只说“报名参加 acm / 蓝桥杯”时直接发布粗糙需求

## 7. Agent 当前能力边界

### 7.1 已实现

- 用户通过聊天描述需求，Agent 会按字段追问并生成草稿
- 用户确认后，Agent 可真正发布需求
- 用户上传文件后，Agent 可分析内容并生成需求草稿
- 用户提出“我想做什么”，Agent 可结合现有需求进行反向推荐
- Agent 可起草联系候选人消息
- Agent 可起草申请加入需求的消息

### 7.2 仍是轻量版的部分

- 主动建议的忽略/稍后处理还没有完整持久化
- 长期记忆面板仍偏展示型，不是成熟的记忆管理系统
- 完整自动调度型执行器仍不是最终产品态
- 实时能力仍以轮询和当前请求链为主，不是完整实时协作系统

## 8. 最近已经修过的重要问题

以下问题在最近几轮对话中已经明确处理过：

- Agent 消息渲染的 XSS 风险
- Agent 会话/任务接口的权限校验问题
- 长会话消息加载顺序问题
- 记忆摘要重复堆叠问题
- 上传后草稿与任务状态不同步问题
- 匹配页起草私信状态串人问题
- 前端构建报错与契约测试不一致问题
- 消息页路由复用不刷新问题
- 页面整体无法下滑、内容被锁死的问题
- Agent 草稿确认发布被连点后生成多条重复需求的问题
- 匹配任务重复触发与删除需求后匹配仍继续运行的问题
- 需求删除失败时前端只显示笼统错误、不暴露真实原因的问题
- Agent 右侧工具栏过长、下部执行状态看不到的问题
- Agent 将“帮我找现有需求”误判为“发布需求”的问题：已通过语义路由与现有需求发现链路强化
- 文件分析后生成多个需求草稿但不可选择的问题：已改为可选择卡片，避免用户不知道会发布哪一条
- 候选人被选中后，候选人侧缺少可交互入口的问题：已在我的需求/被选中需求视角补强
- 申请/匹配完成后，另一方申请状态仍停留在待处理的问题：已补齐事件流转，需求结束后相关待处理申请会进入终态
- 需求发布页过早发布粗糙需求的问题：Agent 现在会继续追问技能、方向和人数模式
- 单人需求的 AI 描述生成多人队友文案的问题：后端与前端均已传递并校正 `selection_mode`
- 切换页面导致需求发布表单、申请草稿、匹配私信草稿丢失的问题：已新增本地草稿持久化工具并接入关键页面
- AI 起草申请/私信只读取少量用户信息的问题：已改为接入完整 `build_user_context` 用户画像

## 9. 当前推荐演示路径

### 9.1 发布方视角

推荐主线：

1. 登录演示账号
2. 进入 Agent 工作台
3. 通过聊天或上传文件描述一个需求
4. Agent 追问并生成需求草稿
5. 确认发布
6. 查看匹配结果
7. 比较候选人
8. 起草私信
9. 跳转消息页沟通

演示小技巧：

- 可以先在发布页填写一半内容或让 AI 生成描述，然后切换到其他页面再返回，展示草稿不会丢失
- 如果选择“单人”，可以展示 AI 生成内容不会再写成“2-3 个队友”

### 9.2 参与方视角

推荐副线：

1. 用户表达“我想做什么”
2. Agent 推荐现有适合参与的需求
3. 用户查看推荐需求
4. Agent 起草申请消息
5. 一键申请并进入沟通

演示小技巧：

- 可以让 Agent 在需求详情页起草申请，切换页面后返回，展示申请草稿仍在
- 起草文案会结合当前登录用户的技能、画像和历史信息，可用于讲“上下文知识库”

## 14. 下一步最值得做的方向

如果继续打磨演示质量，优先级建议如下：

1. 做一轮完整浏览器实走查，覆盖发布方与参与方双主线
2. 清理和固定演示数据，避免旧状态干扰路演
3. 统一文案、空状态、按钮语义和提示语
4. 继续优化 Agent 工作台的可视层次和操作效率
5. 演示前确认设置页 API Key、模型调用、fallback 三种状态都能稳定解释
6. 如果赛后继续做，再推进更完整的自动执行器、后端草稿同步和长期记忆能力
