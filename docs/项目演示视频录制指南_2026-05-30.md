# 校园 AI 互助撮合平台项目演示视频录制指南

> 用途：给负责录制项目演示视频的队友使用。目标是用一条不太长的视频，清楚展示“平台能解决什么问题、AI 能做什么、业务链路是否闭环”。

## 1. 建议视频时长

建议控制在 **4-5 分钟**，最长不要超过 **6 分钟**。

推荐节奏：

- 0:00-0:25：项目一句话介绍
- 0:25-1:20：Agent 辅助发布需求
- 1:20-2:10：匹配结果与候选人选择
- 2:10-2:50：消息沟通闭环
- 2:50-3:45：参与方主动申请或被选中视角
- 3:45-4:25：AI 能力与系统设置/技能封装亮点
- 4:25-4:50：总结收束

如果录制当天网络或模型响应慢，优先保证主链路：**登录 -> Agent 草稿 -> 发布需求 -> 匹配候选人 -> 消息沟通**。

## 2. 录制前准备

### 2.1 打开服务

后端健康检查：

```text
http://127.0.0.1:8000/api/health
```

预期返回：

```json
{"status":"ok"}
```

前端地址：

```text
http://127.0.0.1:5173
```

### 2.2 准备账号

建议使用：

- `alice / 123456`：发布方主视角
- `iris / 123456`：被选中的候选人视角
- `bob / 123456`：主动申请视角

建议提前开两个浏览器窗口：

- 普通窗口登录 `alice`
- 无痕窗口登录 `iris` 或 `bob`

这样录制时不用频繁退出登录。

### 2.3 准备演示数据

建议提前准备一条适合演示的需求，例如：

```text
标题：校园黑客松前端和路演队友
描述：我们正在做校园 AI 互助撮合平台，希望找一位熟悉 Vue、界面设计或项目演示的同学，一起完善前端交互、准备路演材料和现场演示。
人数模式：多人
```

如果 Agent 现场生成较慢，可以直接使用已有需求继续演示匹配和沟通。

### 2.4 录屏设置

- 分辨率建议：`1920x1080`
- 浏览器缩放：`90%` 或 `100%`
- 录制方式：OBS、Xbox Game Bar、PowerPoint 录屏均可
- 不要录入完整 API Key
- 关闭无关通知、聊天软件弹窗和浏览器下载栏
- 鼠标移动慢一点，点击后停 1-2 秒，让评委看清页面变化

## 3. 推荐视频结构与逐段解说

### 第 1 段：开场介绍，约 20 秒

画面：

- 打开平台首页或需求广场。
- 鼠标简单指向导航栏，包括需求广场、发布需求、我的需求、智能助手、消息等入口。

解说词：

```text
大家好，我们的作品是校园 AI 互助撮合平台。它面向比赛组队、课程项目、大创申报和技术求助等校园协作场景，帮助学生把模糊想法整理成清晰需求，再通过 AI 匹配找到合适的队友，并完成申请、选择和站内沟通闭环。
```

录制要点：

- 不要一开始就讲技术细节。
- 先讲“解决校园协作找人难、描述难、沟通断链”的问题。

### 第 2 段：Agent 辅助发布需求，约 55 秒

画面：

1. 使用 `alice` 登录。
2. 打开“智能助手”。
3. 输入：

```text
我想参加校园黑客松，帮我发布一个找前端和路演队友的组队需求
```

4. 根据 Agent 追问回答需求标题、技能方向和人数模式。
5. 展示 Agent 生成的需求草稿。
6. 点击确认发布。

解说词：

```text
首先演示发布方视角。用户不需要一开始就写完整需求，只要用自然语言告诉 Agent 自己想做什么。Agent 会判断这是发布需求场景，并继续追问标题、技能方向、人数模式等关键信息，避免生成过于粗糙的需求。信息补齐后，Agent 会整理成可发布草稿，最终由用户确认后才真正发布。
```

如果现场不想等 AI：

```text
这里也可以看到，平台支持由 Agent 生成结构化需求草稿。为了保证演示节奏，我们直接使用已经生成好的草稿继续发布。
```

录制要点：

- 一定要展示“用户确认发布”，体现安全可控。
- 如果出现多条草稿，点击其中一张卡片，说明可以选择发布，不会一股脑全部发布。
- 如果选择“单人”，可以顺手展示生成内容不会写成“2-3 个队友”。

### 第 3 段：查看匹配结果，约 45 秒

画面：

1. 发布成功后进入匹配结果页。
2. 展示候选人卡片。
3. 展示候选人对比表。
4. 指向匹配理由、技能标签、候选人简介。

解说词：

```text
需求发布后，系统会根据需求描述、技能标签和用户画像生成候选人匹配结果。这里不是简单列出用户，而是给出候选人的技能、简介、匹配分数和推荐理由。发布方可以通过候选人卡片和对比表快速判断谁更适合当前需求。
```

录制要点：

- 不要每个候选人都讲，挑 1-2 个重点讲。
- 讲清楚“为什么推荐”，不要只说“这里有匹配结果”。

### 第 4 段：选择候选人与消息沟通，约 40 秒

画面：

1. 在匹配页选择 `iris` 或点击“起草私信”。
2. 展示 AI 生成的私信内容。
3. 点击联系，进入消息页。
4. 发送一句消息：

```text
你好，我们今晚可以一起确认一下黑客松分工吗？
```

解说词：

```text
匹配之后，平台继续帮助发布方推进沟通。用户可以让 AI 根据需求和候选人信息起草私信，也可以直接进入站内消息。这样从发布需求、看到候选人，到真正发起沟通形成闭环，不会停留在一个静态推荐列表。
```

录制要点：

- 展示消息发送成功即可，不要长时间停留。
- 私信内容如果很长，只读重点，不必逐字念。

### 第 5 段：被选中用户视角，约 40 秒

画面：

1. 切换到 `iris` 账号。
2. 打开“我的需求”。
3. 展示“我被选中的需求”卡片。
4. 点击查看需求或去沟通。

解说词：

```text
接下来切换到候选人视角。被发布方选中后，用户不需要猜自己该去哪里处理事件，可以直接在我的需求页面看到自己被选中的需求，并继续查看详情或进入沟通。这解决了过去匹配状态只在发布方可见、参与方无感的问题。
```

录制要点：

- 这段很重要，用来体现“双边状态闭环”。
- 如果 `iris` 页面已有旧数据，选一条清楚的卡片讲即可。

### 第 6 段：主动申请已有需求，约 45 秒

画面：

1. 切换到 `bob` 账号。
2. 打开需求广场。
3. 进入 `alice` 发布的需求详情。
4. 点击“让 AI 帮我写申请”或直接填写申请。
5. 提交申请。
6. 打开“我的申请”查看状态。

解说词：

```text
平台不只支持发布方找人，也支持参与方主动寻找机会。用户可以在需求广场看到已有需求，进入详情后让 AI 根据自己的技能和用户画像起草申请内容，然后提交申请。申请提交后，用户可以在我的申请页面持续查看待处理、已通过或未通过状态。
```

如果时间不够：

```text
这里可以简短展示需求详情页和我的申请页，不一定完整提交新申请。
```

录制要点：

- 如果视频已经接近 5 分钟，可以把这一段压缩到 25 秒。
- 重点讲“双边撮合”，不要陷入申请表单细节。

### 第 7 段：AI 能力与技术亮点，约 40 秒

画面：

可以选择其中 1-2 个画面，不要全部展示：

- 打开系统设置页，展示 API 设置入口，但不要显示完整 Key。
- 打开 `/api/skills`，展示技能列表。
- 回到 Agent 工作台，展示语义路由、文件分析或草稿卡片。

解说词：

```text
从技术上看，我们把大模型能力拆成了 Prompt、Skill、Agent 和事件链路。系统包含语义路由、文件读取、标签提取、向量匹配、匹配解释、内容审核和上下文摘要等技能。用户输入后，Agent 会先判断真实意图，再决定是发布需求、查找已有需求、起草申请还是推进匹配流程。
```

如果展示系统设置页：

```text
系统设置页支持模型 API 配置，演示时我们会遮挡密钥。即使外部模型临时不可用，平台的需求、匹配、申请和消息主链路仍可以继续运行。
```

录制要点：

- 不要把 API Key 完整录进去。
- 讲能力覆盖：提示词工程、上下文知识库、智能体应用、接口集成、技能封装、安全管控和模型适配。

### 第 8 段：结尾总结，约 20 秒

画面：

- 回到需求广场、我的需求或 Agent 工作台。
- 停在一个信息完整、视觉清晰的页面。

解说词：

```text
总结一下，这个平台把校园协作中的需求表达、AI 整理、智能匹配、主动申请和消息沟通串成完整闭环。我们希望它成为校园里的 AI 协作入口，让学生想做一件事时，不只是发帖，而是能被 Agent 帮助讲清楚、找到人，并真正推进合作。
```

录制要点：

- 语速放慢，给视频一个自然结束。
- 不要在最后继续打开新页面。

## 4. 4 分钟精简版脚本

如果赛事对视频时长比较严格，使用下面版本。

### 0:00-0:20 开场

```text
我们的作品是校园 AI 互助撮合平台，面向比赛组队、课程项目和技术求助场景，帮助学生发布需求、找到合适队友，并完成沟通闭环。
```

### 0:20-1:20 Agent 发布需求

```text
用户只需要用自然语言告诉 Agent 自己想参加黑客松并寻找队友。Agent 会追问标题、技能方向、人数模式等关键信息，然后生成可发布草稿。最终发布由用户确认，保证过程可控。
```

### 1:20-2:05 匹配候选人

```text
发布后系统会根据需求语义、技能标签和用户画像生成候选人匹配结果，并展示技能、简介、分数和推荐理由。发布方可以通过候选人卡片和对比表快速选择合适队友。
```

### 2:05-2:45 消息沟通

```text
匹配之后，系统还能帮助起草私信，并直接进入站内消息。这样从提出需求到找到人、发起沟通形成完整闭环。
```

### 2:45-3:25 参与方视角

```text
切换到参与方后，可以看到自己被选中的需求，也可以主动申请加入已有需求。申请状态会持续流转，避免出现发布方已完成匹配但参与方仍不知道结果的问题。
```

### 3:25-4:00 技术总结

```text
技术上，我们将大模型能力拆成 Prompt、Skill、Agent 和事件链路，覆盖语义路由、文件分析、标签提取、向量匹配、匹配解释、内容审核和上下文摘要等能力。平台不是普通聊天机器人，而是一个可执行的校园协作 Agent 工作流。
```

## 5. 录制时不要做的事

- 不要展示完整 API Key。
- 不要临时重置数据库。
- 不要在视频里长时间等待模型生成。
- 不要反复解释测试细节，视频重点是产品闭环。
- 不要展示控制台报错或无关日志。
- 不要把所有页面都点一遍，优先展示最有说服力的主链路。

## 6. 如果 AI 响应慢的兜底话术

```text
这里由于外部模型响应可能受网络影响，我们使用已经生成好的草稿继续演示。平台的核心业务链路，包括发布、匹配、申请和消息沟通，不依赖单次模型调用是否成功。
```

## 7. 最终检查清单

- 视频时长控制在 4-5 分钟。
- 画面中没有完整 API Key。
- 至少展示一次 Agent 生成或整理需求。
- 至少展示一次匹配候选人和推荐理由。
- 至少展示一次消息沟通。
- 至少展示一次参与方视角，例如被选中需求或我的申请。
- 解说中讲清楚“AI Agent 工作流”而不是普通发帖平台。
- 结尾有一句完整总结。
