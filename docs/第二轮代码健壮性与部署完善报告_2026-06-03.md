## 三、关键改进详细说明

### 3.1 SECRET_KEY 强制配置

**问题**: `config.py` 中 `SECRET_KEY` 硬编码默认值 `"dev-secret-key"`，如果部署时忘记配置 `.env` 文件，JWT Token 将使用可预测的密钥签发。

**修复**: 
- 默认值改为空字符串 `""`
- 启动时检测到空值 → 打印错误日志 → `sys.exit(1)` 拒绝启动
- 日志中提示生成命令：`python -c "import secrets; print(secrets.token_urlsafe(32))"`

### 3.2 文件日志与审计

**问题**: 第一轮使用 `RotatingFileHandler` 导入但未启用，日志仅输出到 stderr，服务重启后不可追溯。

**修复**: 
- 同时输出到 stderr (开发调试) 和 `backend/logs/app.log` (持久审计)
- 单文件 10MB 上限，保留最近 10 个轮转文件
- `.gitignore` 排除 `logs/` 目录

### 3.3 密码强度与用户名校验

**问题**: 注册接口仅检查用户名重名，无密码强度和格式校验。

**修复**:
- 密码：≥6 位、≤128 位、禁止空格
- 用户名：2-20 字符、仅允许字母数字下划线连字符
- 校验失败返回明确的中文错误消息

### 3.4 API Key 检测限流

**问题**: `/api/settings/test-api-key` 端点虽需登录，但无频率限制，可被频繁调用消耗外部 API 额度。

**修复**: 增加 `RateLimiter` 检查，按客户端 IP 限制 10 次/分钟。

### 3.5 容器化部署

新增完整的 Docker 部署方案：
- **后端**: Python 3.12-slim，非 root 用户运行，4 个 Uvicorn workers，Healthcheck 端点
- **前端**: 多阶段构建（Node 构建 → Nginx 1.27-alpine），Gzip 压缩，安全响应头
- **编排**: docker-compose.yml，环境变量驱动，数据卷挂载，网络隔离

### 3.6 CI/CD 流水线

GitHub Actions 工作流包含 4 个 Job：
1. `backend-lint`: Python 语法编译检查
2. `backend-test`: 契约测试 + 冒烟测试
3. `frontend-build`: TypeScript 类型检查 + Vite 构建
4. `docker-build`: Docker 镜像构建验证

### 3.7 缺失脚本补全

- `seed.py`: 幂等创建 11 个演示用户（含技能标签、学校、个人简介）和 8 条需求
- `download_models.py`: 双通道下载 Qwen3 模型（sentence-transformers 优先，huggingface_hub 回退）
- `reset_db.py`: 安全重置数据库，需输入 `YES` 确认，清理 `.db/.db-wal/.db-shm/skill_graph.json`
